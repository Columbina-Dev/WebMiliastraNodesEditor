# "Genshin Impact - Miliastra Wonderland" Node Graph Simulator

This project recreates the node graph editor from "Genshin Impact - Miliastra Wonderland" to allow prototyping node graphs without opening Genshin Impact. It supports creating, importing, exporting, and organizing node graph projects in the browser.

> [!WARNING]  
> **Note:** This project is a fan-made creation and is not affiliated with miHoYo / HoYoverse. All referenced materials belong to their original copyright holders.

> [!WARNING]  
> Over 90% of the code in this project is generated by AI.

## Repository Structure

- `web/` – A Vite-based React web application.
- `iconsWorkingDir/` - Some working files of the recreated svg icons from the official editor. `Drawing1.dwg` contains all icons. Recommended to open using AutoCAD Electrical 2023. <small>P.S.: I have never systematically learnt AutoCAD / Photoshop, and the svg icons are only made roughly.</small>
- `web/src/data/` – Node definitions based on the official editor.
- `web/src/types/node.ts` – Definitions for the node system.
- `web/src/utils/` – Additional utility functions for IO, validation, drag-and-drop, device type detection, etc.
- `web/public/tutorial/` - Locally stored "Genshin Impact Miliastra Wonderland: General Guide".
- `web/src/external/` - Some authorized third-party resources, currently including effects previewing tool (From: https://ys.keqizu.com/)

```bash
git clone https://github.com/Columbina-Dev/WebMiliastraNodesEditor.git
cd WebMiliastraNodesEditor/web
npm install

```

`npm run dev` defaultly starts webpage @ http://localhost:5173/ 。

## Save Management

### Auto Saving and Update Adaption

The web app will store recent projects and drafts in the browser's `localStorage`:

- When opening the new version* for the first time, it will automatically scan saves from old version and convert them into a complete project, uniformly placed in the `server/entity/default` directory.  
- Auto-saved and historical projects are sorted chronologically, also provides a one-click export of all projects as a zip file function.  
- You can rename projects in "File/Edit Project Info" without needing to export to edit manually and re-import.

\* - new version refers to v0.9.70 and later. Earlier versions only supported saving with a single node graph.

### Resource Explorer Validation

The resource explorer displays in a hierarchy of `server <or> client → category → tab (folder) → JSON node graph`:

- It loads node definitions from `nodeDefinitions.server.ts` / `nodeDefinitions.client.ts` (falls back to `nodeDefinitions.ts` if empty).  
- When opening a node graph, it verifies that `GraphDocument.environment` matches the directory and ensures the node types exist in the allowed list for the current environment.  
- If errors are found, the list will be marked in red with detailed reasons; the node graph is prohibited from being opened directly but can be exported as `.server.json` or `.client.json` for offline repair. Please modify the `environment` key in the JSON to the correct value based on the error.  

## Touch and Mobile Optimization

Partial touch and mobile optimizations have been made, but full compatibility cannot be guaranteed at this time:

- The browser's default two-finger zoom is disabled, and the canvas uses native gestures to handle zooming.  
- Two-finger tap is equivalent to right-click on desktop, allowing the menu to pop up anywhere on the canvas.

### Obtain Official Tutorial HTML Files

Modify the `scripts/fetch_tutorial_html.py` script if needed, else run the following command **at the root directory of the repository**:

```bash
python scripts/fetch_tutorial_html.py
```

The HTML files will be stored to `web/public/tutorial/knowledge` and `web/public/tutorial/course` .

### Find Official's Webapp Version

Visit [OS Server Guide](https://act.hoyoverse.com/ys/ugc/tutorial/) or [CN Server Guide](https://act.mihoyo.com/ys/ugc/tutorial), the value of `window.__APP_VERSION__` in the page source code is the current official version number for the guides.

### Limitations

1. All official HTML files are only available in Simplified Chinese. If you need other languages, you can `curl https://act-webstatic.hoyoverse.com/ugc-tutorial/knowledge/sea/<language_code>/textMap.json` to get the corresponding language's `textMap.json`, and modify `web/src/components/TutorialPage.tsx` and `web/src/app.tsx` accordingly. You can refer to [https://milidocs.tiiny.site/](https://milidocs.tiiny.site/), which uses the same method as the official site (using text map to replace all text in Simplified Chinese HTML). Due to the complexity of this modification, detailed instructions are not provided here; please research on your own.

2. Due to code limitations, currently only `Knowledge Base` and `Courses` can be correctly displayed. If the official site updates more categories in the future, corresponding modifications to `web/src/components/TutorialPage.tsx` and `web/src/app.tsx` will be required to add the new logic.

## JSON Graph Document Explanation

(Intro generated by AI)
The editor reads and writes node graphs following the `GraphDocument` structure (defined in `web/src/types/node.ts`):

```jsonc
{
  "schemaVersion": 2,
  "name": "Example Graph",
  "environment": "server",          // Optional: server | client, if not filled, it will be automatically supplemented based on the directory during import
  "createdAt": "2024-01-01T00:00:00.000Z",
  "updatedAt": "2024-01-02T00:00:00.000Z",
  "nodes": [
    {
      "id": "node_1",
      "type": "action.printString",
      "label": "Print String",
      "position": { "x": 320, "y": 180 },
      "data": {
        "overrides": {
          "text": "Hello Miliastra!"
        },
        "controls": {
          "loop": false
        }
      }
    }
  ],
  "edges": [
    {
      "id": "edge_1",
      "source": { "nodeId": "node_event", "portId": "flowOut" },
      "target": { "nodeId": "node_1", "portId": "flowIn" }
    }
  ],
  "comments": [
    {
      "id": "comment_1",
      "text": "You can write comments here",
      "nodeId": "node_1",
      "pinned": true
    }
  ]
}
```

Import validation steps:

1. Use `zod` to parse and validate required fields, enum values, coordinates, and other formats.  
2. If `environment` is missing, it will be supplemented based on the directory; if it conflicts with the directory, an error will be reported.  
3. Check whether the node type exists in the current environment's node definition set; invalid types will be listed in the error list.  
4. Connection edges will validate port types (flow/data) and data type compatibility.  

When validation fails, the resource manager will display the reason in the "Remarks" column, and users need to export the JSON, manually fix it, and re-import it.

## Node Definition Format

(Intro generated by AI)  
Node definitions use the `NodeDefinition` interface (see `web/src/types/node.ts`). Core fields:

```ts
interface NodeDefinition {
  id: string;                            // Unique identifier, recommended format "type.function"
  displayName: string;                   // UI display name
  category: string;                      // Hierarchical directory separated by /, e.g., "Execution Nodes/Common"
  kind: 'event' | 'action' | 'query' | 'flow-control' | 'logic' | 'math' | 'data';
  headerColor?: string;                  // Node title color
  ports: PortDefinition[];               // Port definitions (see below)
  controls?: NodeControlDefinition[];    // Panel controls, such as dropdowns, input boxes, etc.
  description?: string;                  // Optional: description displayed in the inspector panel
}

interface FlowPortDefinition {
  id: string;
  label: string;
  kind: 'flow-in' | 'flow-out';
  allowMultipleConnections?: boolean;
}

interface DataPortDefinition {
  id: string;
  label: string;
  kind: 'data-in' | 'data-out';
  valueType: ValueType;                  // Defined in types/node.ts || e.g.: 'bool' | 'string' | 'vector3'
  allowMultipleConnections?: boolean;
  defaultValue?: unknown;
  enumValues?: Array<{ label: string; value: string | number }>;
}
```

### Node Definition Files

> [!IMPORTANT]  
> Note that in `web/src/data/nodeDefinitions.ts` file, **ALL** node definitions are inferred by LLM AI based on screenshots of official node graph editor, and there may be errors or incompleteness. If you found any errors or omissions, please raise them in the Issue.

- The lists of all nodes usable in server and client node graphs should be written separately in `web/src/data/nodeDefinitions.server.ts` and `web/src/data/nodeDefinitions.client.ts`.
- If both files are temporarily empty, both types of node graphs can use all nodes defined in `nodeDefinitions.ts`.

Example list:

```ts
export const serverNodeList = [
  "action.printString", 
  "action.setLocalVariable",
  // ...
] as const;
```
